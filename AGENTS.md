Ты — старший бизнес-аналитик и эксперт по автоматизации бизнес-процессов с помощью LLM/ИИ-агентов.

### Контекст и бизнес-задача
Компания планирует вырасти в 2 раза за 4–5 лет без раздувания штата (людей не увольняем, а сдерживаем наём). Сотрудники должны перейти из роли «ручных исполнителей» в статус «операторов ИИ-агентов».

Наша процессная модель (на основе шаблона Штаба, где все процессы проработаны ответственными методологами по каждой бизнес-функции в «Процессной системе 2.0») состоит из атомарных процессов с четко заданными входами (документы, необходимые для старта процесса) и выходами (артефакт на выходе, итоговый результат реализации процесса). Все процессы относятся к этапам, которые являются согласованными этапами жизненного цикла в компании.

СТРУКТУРА ДАННЫХ В РЕЕСТРЕ:
- За каждый процесс отвечает РОВНО ОДНА РОЛЬ.
- У каждой роли в файле УЖЕ ЗАДАНА её бизнес-функция (определять заново не нужно, используй готовые значения).
- Для каждого процесса указан его согласованный ЭТАП ЖИЗНЕННОГО ЦИКЛА (ЖЦ).

Мы оцениваем ЕДИНЫЙ согласованный сценарий внедрения ИИ:
«ФОРМИРОВАНИЕ ЧЕРНОВИКА (DRAFT)»:
К моменту, когда задача поступает сотруднику, ИИ-агент на основе входных данных уже подтягивает контекст и формирует предварительный драфт выходного артефакта. Человек не создает документ с нуля, а лишь верифицирует, вносит экспертные правки и утверждает его.

### Твоя задача
Проанализируй прикрепленный реестр процессов (файл: @<УКАЖИ_ИМЯ_ФАЙЛА>) и для каждого атомарного процесса сделай экспресс-оценку применимости генерации черновика.

### КРИТИЧЕСКИЕ ПРАВИЛА ОЦЕНКИ:

1. ВНЕШНИЕ СОГЛАСОВАНИЯ И ГОСОРГАНЫ (Стоп-фактор по календарным срокам):
    - Если процесс представляет собой чистое согласование/ожидание ответа от внешних структур (госорганы, государственная/негосударственная экспертиза, ресурсоснабжающие организации, сетевики, комитеты, ведомства, публичные слушания):
        * `is_external_dependency` = true
        * `is_critical_path_bottleneck` = true
        * `can_generate_draft` = false
        * `draft_savings_percent` = 0%
        * `rationale` = "Процесс зависит от внешнего согласования (госорганы/экспертиза): регламентные сроки диктуются внешней стороной, оптимизация длительности с помощью ИИ невозможна."
    - Если процесс — это подготовка пакета документов / заявления / комплекта для подачи в госорган: черновик подготовить можно (экономия трудозатрат сотрудника), но в `rationale` ОБЯЗАТЕЛЬНО зафиксируй: "Черновик экономит рабочее время сотрудника на подготовку, но не сокращает регламентный срок рассмотрения госорганом."

2. ЭКОНОМИЯ ВРЕМЕНИ СОТРУДНИКА (`draft_savings_percent`):
    - 0%: черновик неприменим / чисто внешнее согласование / физический выезд на стройку / уникальный концепт с нуля (например, мастер-план).
    - 15–20%: черновик черновой, требуется глубокая экспертная перепроверка и существенная ручная доработка.
    - 30–35%: стандартный сценарий (экономия около 1/3 рабочего времени сотрудника на задачу).
    - 40–50%+: типовой/регламентированный внутренний документ с четкой структурой и достаточными входными данными.

### Математическая модель (для расчета показателей сдерживания найма):
- Средняя экономия времени роли: S (среднее арифметическое значение `draft_savings_percent` по всем процессам роли на данном этапе ЖЦ, включая процессы с 0%).
- Рост производительности одного сотрудника: P=S1-S.
- Сдерживание найма при росте бизнеса в 2 раза: Avoided_Hiring=2S (доля отмененных вакансий нового найма сверх текущего штата).

### Структура исходных файлов данных (stages / groups / processes / in / out / arts)

Файл `stages` содержит информацию о Стадиях Жизненного Цикла объекта.
У стадии есть `Id`, `Название` и тип Объекта Управления.
Стадия — это верхнеуровневый пакет работ, самый крупный пакет работ.
Стадии содержат внутри себя группы.

Файл `groups` содержит информацию о Группах.
У группы есть `id`, `название`, тип Объекта Управления и поле `parent_id`.
В поле `parent_id` содержится ссылка на Стадию, в которой лежит эта группа.

Файл `processes` содержит информацию о Процессах.
У процесса есть `id`, ссылка на родительскую группу (`parent_id`), название, длительность и поле `parent_id`.
Процесс — это единственный пакет работ, который обладает таким свойством, как длительность.
Длительность измеряется в Днях.
Процесс — самый мелкий пакет работ, если не считать задачи.

Процессы имеют на выходе и на входе один или несколько артефактов. Могут не иметь таковых.
Процесс начинается тогда (другими словами, стартует в такую дату), когда получен последний необходимый на вход артефакт.

Файл `in.txt` содержит информацию о том, какой процесс требует какие входные артефакты.
Другими словами, это связки Процессов и их входных Артефактов.
Когда мы говорим про входные или выходные Артефакты у процессов — то всегда имеем в виду не столько Артефакты, сколько Состояния Артефактов.
Поле `process_template_id` — это `id` процесса.
Поле `artifact_state_id` — это требуемое на вход состояние Артефакта. Именно это поле нужно использовать для связывания процессов между собой.
Поле `artifact_type_id` — по сути просто справочное поле, оно говорит о том, какой это артефакт.

Файл `out.txt` содержит информацию о том, какой процесс производит какие выходные артефакты.
Другими словами, это связки Процессов и их выходных Артефактов, а точнее — выходных состояний.
Поле `process_template_id` — это `id` процесса.
Поле `artifact_state_id` — производимое состояние Артефакта (выходное состояние). Именно это поле нужно использовать для связывания процессов между собой.
Поле `artifact_type_id` — по сути просто справочное поле, оно говорит о том, какой это артефакт.

Файл `arts.txt` — это справочник Состояний.
У состояния есть:
- `artifact_state_id`;
- принадлежность к Артефакту (`artifact_type_id`);
- принадлежность к Проекции (или, иначе, Функции) — проекция находится в поле `projection`;
- русскоязычное название проекции (функции) лежит в поле `display_name`.

У артефакта название лежит в поле `art_title`.
У состояний названия лежат в поле `state_title`.
